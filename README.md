# mlpowermeter

Physics-grounded energy measurement and prediction for machine learning
workloads, from classical models through deep networks to reinforcement
learning agents. This repository holds the `tomlml` package, the experiment
protocol, the experimental record, and the paper source for the TOML
(Transistor Operations for Machine Learning) study targeting ICLR.

**Status:** instrumentation phase. No scientific results are claimed yet. The
first experiment (EXP-001) validates the measurement stack on both target
platforms; nothing downstream starts until it passes on both.

## What this is

TOML predicts the energy of an algorithm from counts of physical events
(transistor operations for arithmetic, memory traffic, GPU command dispatch,
and fused sequential execution) rather than from FLOPs. Earlier papers in the
program established the framework (FLAIRS-39), applied it to 37 signal
processing algorithms on an RTX 4090 and an A100 (IEEE MLSP 2026,
[TOMLSignals](https://github.com/jemsbhai/TOMLSignals)), and extended it to
multi-tenant cloud settings (IEEE CloudCom 2026, TOMLCloud).

This study asks whether a single device-calibrated operation model predicts
measured training and inference energy across the major ML algorithm families,
and whether it predicts the crossover regimes where FLOPs-based reasoning gives
the wrong answer: dense versus low-rank, dense versus sparse, dispatch-dominated
small-batch execution (where reinforcement learning agents spend most of their
time), and GPU versus CPU. Predictions are registered before the held-out
platform is measured. The full hypothesis list, gates, and claim discipline are
in `docs/blueprint_2026-09-09.md`; decisions that modify the blueprint are
recorded in `DECISIONS.md`.

## Repository layout

```
mlpowermeter/
  LOGBOOK.md            experimental logbook: every experiment, planned before it runs
  findings.md           curated summary plus append-only raw findings log
  DECISIONS.md          dated decision log (protocol and scope changes)
  configs/              experiment configurations (base.yaml plus one file per EXP)
  data/                 datasets (not committed), checksums, and provenance notes
  docs/                 blueprint, quickstart guides, protocol notes
  experiments/          per-experiment outputs: frozen config, environment, seeds,

  figures/              publication figures, regenerated by scripts
  notebooks/            exploratory analysis only; never the source of a paper number
  paper/                LaTeX source
  scripts/              entry points (run_experiment.py, snapshot_env.py) and SLURM jobs
  src/tomlml/           the package: measurement, TO models, utilities, analysis
  tests/                pytest suite
```

## Setup

The reference software stack is pinned to the laptop environment used to
develop the measurement code. Both platforms should match it; where a platform
cannot, `environment.json` in each experiment directory records the actual
versions and the deviation is noted in the logbook.

Reference stack: Python 3.12, torch 2.6.0 (CUDA 12.4 wheels, cuDNN 9.1),
numpy 2.0.2, scipy 1.17.1, scikit-learn 1.5.2, nvidia-ml-py 13.595.45.

### Windows laptop (RTX 4090 Laptop GPU)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
pip install -e .
pytest tests -v
```

### Linux SLURM cluster (A100 SXM4 40 GB)

See `docs/QUICKSTART_A100.md` for the full walkthrough, including the SLURM job
template and how results come back into the repository. The short version:

```bash
python3 -m venv ~/venvs/tomlml && source ~/venvs/tomlml/bin/activate
python -m pip install --upgrade pip
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
pip install -e .
pytest tests -v
```

Note on NVML bindings: this project depends on `nvidia-ml-py` (the NVIDIA
maintained package). If the legacy `pynvml` package is also installed it acts
as a deprecation shim and is harmless; do not install both from scratch.

## Running an experiment

Every experiment is defined by a config in `configs/` and a planned entry in
`LOGBOOK.md`. The runner freezes the config, snapshots the environment, records
seeds and the git commit, and writes everything under
`experiments/exp_XXX_name/<platform-tag>/`.

```powershell
python scripts/run_experiment.py --config configs/exp_001_instrumentation.yaml
```

On the cluster the same command runs inside `scripts/slurm/exp_001.sbatch`.

## Measurement principles

1. Two energy quantities are recorded for every window at CUDA-synchronized
   boundaries: the NVML cumulative energy counter delta and the trapezoid
   integral of 50 ms power readings. The instrumentation gate (EXP-001)
   decides per platform which one is the energy source, by testing whether
   the counter is monotonic, updates often enough, and agrees with the
   integral; the other remains a recorded consistency check on the same
   sensor. On the RTX 4090 Laptop GPU the counter failed that test
   (DECISIONS.md D-009), so that platform uses the power integral.
2. The torch device is resolved to the physical GPU by UUID, so measurements
   under `CUDA_VISIBLE_DEVICES` remapping (SLURM) attach to the right device.
   The mapping is verified and recorded in every manifest.
3. Gross device energy is the main operational quantity; idle-subtracted dynamic
   energy is reported as a sensitivity analysis with the idle method logged.
4. Thermal state is settled before baselines, run order is randomized within
   blocks, and every measurement window is validated for sufficiency before
   being used in a reported number.
5. Other processes on the GPU are checked before and after every measurement;
   a contaminated window is recorded and excluded with its reason logged.
6. Every reported number traces to an experiment ID, a commit SHA, a frozen
   config, and a seed file. No number in the paper is typed by hand.
